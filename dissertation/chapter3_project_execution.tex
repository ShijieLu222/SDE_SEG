\chapter{Project Execution}
\label{chap:execution}

This chapter documents how the reproduction experiments and the cross-task
consistency loss extension were carried out in practice, including the
computing environment, dataset configuration, training pipeline, use of the
PAD multi-task decoder, and the organisation of individual experiment
groups. Throughout, this project adopts the terminology of the original
paper: Stage~(a) refers to standard supervised learning using all available 
annotated data as the baseline, while Stage~(b) encompasses 
semi-supervised extension mechanisms, including automatic data 
selection~(S), DepthMix data augmentation~(DX), and multi-task 
learning~(MTL).

\section{Experimental Setup}
\label{sec:setup}

\subsection{Computing Environment}
\label{sec:computing-environment}

The reproduction experiments (exp~210--213, corresponding to Tables~1, 3,
5, and~7) were run on the University of Bristol's Isambard-AI
platform~\cite{isambard_ai}, using a single GPU per job. The subsequent
cross-task consistency loss extension experiments (exp~219, exp~220, and
exp~222) were run on the University of Bristol's BluePebble high-performance
computing platform~(BP1) under the SLURM workload manager. Both sets of
experiments followed the same configuration management and random seed
control procedures to ensure traceability and reproducibility.

On BluePebble, each SLURM job was allocated one GPU, eight physical cores,
and 64\,GB of system memory. BP1 is a heterogeneous cluster and node
assignment is managed automatically by SLURM. The cross-task loss
experiments were run predominantly on V100 nodes with 32\,GB VRAM. All
experiments ran within a dedicated Conda environment with pinned
dependencies to ensure consistent behaviour across node types.

\subsection{Training Configuration and Reproducibility}
\label{sec:training-config}

Random seeds were fixed across Python, NumPy, and PyTorch at the start of
every run. Each experiment's full configuration, including experiment ID,
label budget, seed, and all hyperparameters, was logged alongside model
checkpoints to support reproducibility.

All reproduction and extension experiments used a ResNet-101
encoder~\cite{he2016resnet} pretrained on ImageNet~\cite{deng2009imagenet}.
Training used the SGD optimiser with momentum $0.9$ and weight decay
$5\!\times\!10^{-4}$, following a polynomial learning-rate decay schedule
over 40{,}000 iterations. Learning rates were set to $10^{-2}$ for the
decoder, $10^{-3}$ for the backbone encoder, and $10^{-6}$ for the pose
network.

A key resource constraint of this project is that all experiments were run
on a single GPU. Although the University of Bristol's HPC platforms
technically support multi-GPU jobs, this project required running tens of
distinct experiment configurations. Waiting for multiple GPUs to become
simultaneously available would have imposed prohibitively long queue times,
severely compressing the window available for iterative experimentation.
The single-GPU strategy was therefore adopted as a deliberate trade-off:
accepting reduced per-run hardware capacity in exchange for substantially
higher experiment throughput within the available project timeline.

As a direct consequence of the single-GPU constraint, a batch size of~2
was used without Synchronised Batch Normalisation~(SyncBN).
SyncBN is a technique used in multi-GPU training that synchronises the
computation of batch normalisation statistics---specifically the per-channel
mean and variance---across all GPUs at each step, so that the normalisation
is effectively performed over the full cross-GPU batch rather than each
GPU's local shard. In the original paper's multi-GPU setup, SyncBN
produced stable normalisation statistics equivalent to an effective batch
size of~8; in this project's single-GPU setup with batch size~2, batch
normalisation statistics are estimated from fewer samples per step,
introducing greater noise into the normalisation. This is one of the
primary reasons why the reproduced results are systematically slightly
below the original paper across most configurations, with gaps in the
range of approximately $0.2$ to $1.6$\,pp---a discrepancy consistent with
the well-documented sensitivity of semi-supervised methods to effective
batch size.

The practical impact of these hardware constraints is analysed in
Chapter~\ref{chap:evaluation}, where the reproduced results are compared
against the original paper and the proposed $\mathcal{L}_\text{ct}$
variants are evaluated under the same experimental protocol.

All experiment configurations are managed through a centralised
\texttt{experiments.py} module, which maps discrete experiment IDs to
fully specified hyperparameter dictionaries. This acts as the central
configuration reference, reducing configuration drift across runs and
making individual results reproducible from their experiment IDs alone.

\section{Dataset and Feature Representation}
\label{sec:dataset}

The pipeline makes use of two complementary data modalities within the
Cityscapes dataset~\cite{cordts2016cityscapes}: pixel-level semantic
annotations for supervised segmentation, and adjacent temporal frames for
geometric self-supervision.

The 2,975 fine-annotated images form the labelled pool. Low annotation
budgets of 100, 372, and 744 samples are simulated by selecting subsets
from this pool using the author-provided fixed subset indices, thereby
preserving consistency with the original evaluation protocol. For each
target image, a three-frame window consisting of the current frame and its
immediate neighbours supplies geometric cues for self-supervised depth
estimation and geometry-aware components such as DepthMix. These frames
carry no semantic annotations and are used only for photometric and pose
supervision.

Images are resized to $1024\!\times\!512$ and randomly cropped to
$512\!\times\!512$ during training. This resolution balances sufficient
spatial context for boundary-sensitive tasks against single-GPU VRAM
feasibility, particularly for Stage~(b) configurations that maintain two
parallel decoder branches simultaneously.

Several Stage~(b) components require an SDE-pretrained encoder to provide
depth-informed encoder initialisation. The framework of
\cite{hoyer2023ijcv_sde} produces two encoder weight variants, \texttt{fd0}
and \texttt{fd2}, whose properties are described in detail in
Section~\ref{sec:sde}. In brief, \texttt{fd0} applies standard monocular
depth pre-training, optimising the encoder purely for depth estimation;
this risks the encoder drifting away from the ImageNet feature space and
losing semantic representations that are beneficial for downstream
segmentation. \texttt{fd2} addresses this by adding a feature-distance
regularisation term~$\mathcal{L}_F$ during depth pre-training, which
penalises large deviations from the ImageNet-initialised feature space.
This retains useful semantic knowledge while still incorporating geometric
cues from SDE, making \texttt{fd2} a stronger initialisation for the
downstream segmentation task. The author-released checkpoints for both
variants are used throughout and kept fixed across all downstream
experiments.

\section{Use of the PAD Multi-Task Decoder}
\label{sec:pad-decoder}

Both Stage~(b) experiments and the $\mathcal{L}_\text{ct}$ extension are
built on the PAD-Net multi-task architecture~\cite{xu2018padnet}. As
described in Chapter~\ref{chap:technical}, PAD-Net maintains two parallel
decoder branches for depth estimation and semantic segmentation on top of
a shared ResNet-101 encoder, exchanging cross-task information at an
intermediate distillation layer through an attention-guided distillation
module.

In this project's configuration, the distillation layer is placed at
decoder upsampling layer~7, producing feature maps of spatial resolution
$128\!\times\!128$ with 128 channels. The depth features $f_\text{depth}$
and segmentation features $f_\text{seg}$ at this layer serve as the inputs
to $\mathcal{L}_\text{ct}$. The $1\!\times\!1$ convolutional projection
head used by $\mathcal{L}_\text{ct}$ preserves the channel dimensionality
of its input, so its input and output feature maps both have 128 channels.

Two projection directions are evaluated under the single-projection
layout. In single~$(d{\rightarrow}s)$, the depth feature
$f_\text{depth}$ is passed through the projection head to produce a
projected representation $z = \phi(f_\text{depth})$, and the loss
penalises the discrepancy between $f_\text{seg}$ and $z$. In
single~$(s{\rightarrow}d)$, the segmentation feature $f_\text{seg}$---
which receives direct gradient signal from ground-truth labels---is
projected to produce $z = \phi(f_\text{seg})$, and the loss penalises the
discrepancy between $f_\text{depth}$ and $z$. Both variants share the
same $1\!\times\!1$ projection head architecture and identical parameter
count ($16{,}512$ additional parameters).

In addition to the two single-projection variants, a dual-projection
layout is also evaluated. In this setting, two independent
$1\!\times\!1$ convolutional projection heads are used: one projects
$f_\text{depth}$ and the other projects $f_\text{seg}$, and the
consistency loss is computed between the two projected representations.
This doubles the number of additional parameters to $33{,}024$ and
introduces a symmetric alignment constraint in which both feature spaces
are allowed to adapt simultaneously, in contrast to the single-projection
design where one branch remains in its original feature space.

The relative effectiveness of these projection layouts and directions is
evaluated empirically in Section~\ref{sec:ct-calibration-ablation}.

\section{Experiment Groups}
\label{sec:hpc_exec}

The experimental runs fall into two broad groups. The first group
reproduces the core results reported in Tables~1, 3, 5, and~7 of the
original paper~\cite{hoyer2023ijcv_sde}, while the second group evaluates
the proposed cross-task consistency loss extension on top of the PAD-MTL
baseline. The following subsections summarise how each experiment group
was organised.

\subsection{Table~1: Data Selection (exp~211)}

This experiment curates informative labelled subsets under fixed budgets
using three selection criteria: random sampling as a baseline; entropy
sampling, which ranks unlabelled images by model prediction uncertainty;
and SDE-guided selection combining uncertainty sampling~(US) and diversity
sampling~(DS). For each criterion, images are scored and the top-$K$ are
selected to match the target budget of 100, 372, or 744 samples. The
author-provided fixed subset indices ensure exact comparability across
runs.

\subsection{Table~3: Mixing Strategy (exp~210)}

This run evaluates four training strategies under the 372-label and
full-supervision settings: a supervised-only baseline, pseudo-label
self-training, ClassMix, and DepthMix. Semi-supervised variants follow
the official teacher--student framework with exponential moving average
teacher updates and confidence-filtered pseudo-label generation. DepthMix
replaces the binary masks of ClassMix with geometry-consistent composition
masks derived from SDE depth maps, reducing boundary artefacts at class
transitions.

\subsection{Tables~5 and~7: Feature Transfer and Component Ablation
(exp~212, exp~213)}

These runs evaluate SDE-to-segmentation feature transfer using the
\texttt{fd0} and \texttt{fd2} encoder checkpoints~(Table~5), and the
combined effects of data selection~(S), DepthMix~(DX), and multi-task
learning~(MTL)~(Table~7). Table~7 requires eight distinct configurations
to isolate the contribution of each component; each is trained with three
independent seeds~(7, 25, 42) and results are reported as mean\,$\pm$\,std.

\subsection{Cross-Task Consistency Loss Calibration (exp~219, exp~220)}

The calibration of $\mathcal{L}_\text{ct}$ follows a two-phase design that
balances hyperparameter search coverage against result stability within a
limited computing budget.

Running all candidate configurations with three independent seeds from the
outset would require a large number of full training runs of 40{,}000
iterations each, a cost that exceeds the available compute allocation for
this project. The two-phase strategy therefore first uses a single seed to
screen the full search space efficiently, and then applies multi-seed
validation only to the most promising candidates, providing a principled
balance between hyperparameter coverage and statistical reliability.

Phase~I (exp~219) trains configurations formed by three factors---loss
type (cosine similarity vs.\ normalised MSE), projection layout (single
vs.\ dual), and $\lambda_\text{ct} \in \{0.25, 0.50, 0.75, 1.00\}$---for
the full 40{,}000 iterations under a single seed. An additional direction
ablation within the single-projection layout evaluates both
$d{\rightarrow}s$ and $s{\rightarrow}d$ variants, as described in
Section~\ref{sec:pad-decoder}. Seed~7 is used throughout Phase~I so that
all configurations are compared under identical random initialisation
conditions. The purpose of this phase is to identify configurations that
merit further multi-seed validation, while filtering out settings that do
not show competitive performance under the shared single-seed condition.

Phase~II (exp~220) retrains the candidates selected from Phase~I using
three independent seeds~(7, 25, 42) to assess reproducibility. A PAD-MTL
baseline (without $\mathcal{L}_\text{ct}$) is retrained with the same
three seeds in the same submission batch, providing a consistent per-seed
reference for paired comparisons. Each configuration is submitted as an
independent SLURM job, running all three seeds sequentially.

\subsection{Component-Level Ablation of $\mathcal{L}_\text{ct}$ (exp~222)}

Exp~222 evaluates whether the cross-task consistency loss composes well
with the existing framework components (data selection~S, DepthMix~DX,
and multi-task learning~MTL). The ablation covers three component
combinations on the 372-label setting: MTL\,+\,DX, MTL\,+\,S, and
MTL\,+\,DX\,+\,S. For each combination, four $\mathcal{L}_\text{ct}$
variants are trained---covering both projection directions
($d{\rightarrow}s$ and $s{\rightarrow}d$) and both loss types (normalised
MSE and cosine similarity)---yielding twelve ablation configurations in
total. For each of the three component combinations, a matching baseline
without $\mathcal{L}_\text{ct}$ is trained under the same pipeline and in
the same submission batch, providing a paired per-seed reference for each
ablation cell and removing the need for cross-batch comparisons.

All $\mathcal{L}_\text{ct}$ configurations use a single $1\!\times\!1$
convolutional projection head, $\lambda_\text{ct}=1.0$, and bidirectional
gradient flow. The variables within the ablation are the loss formulation 
(MSE versus cosine) and the projection direction ($d{\rightarrow}s$ versus $s{\rightarrow}d$), so
that any performance difference is attributable to these factors rather
than to auxiliary hyperparameter effects. Each configuration is trained
with the same three seeds (7, 25, 42) as the paired baseline, enabling
direct per-seed comparisons.

\section{Summary}
\label{sec:exec_summary}

This chapter has described how the experiments were implemented and
organised in practice. It covered the computing environment, dataset
configuration, model setup, experiment ID mapping, and the design of the
reproduction and extension experiment groups. The reproduction experiments
(exp~210--213) were run on Isambard-AI, while the extension experiments
(exp~219, exp~220, and exp~222) were run on BluePebble. Although the
single-GPU constraint limited the effective batch size and prevented the
use of SyncBN, it allowed a larger number of configurations to be evaluated
within the available project timeline. The effect of this constraint, as
well as the quantitative outcomes of the experiments, is analysed in
Chapter~\ref{chap:evaluation}.
