\chapter{Project Execution}
\label{chap:execution}

This chapter documents how the reproduction experiments and the cross-task
consistency loss extension were carried out in practice, including the
computing environment, dataset configuration, training pipeline, use of the
PAD multi-task decoder, and the organisation of individual experiment
groups. Throughout, this project adopts the terminology of the original
paper: \textbf{Stage~(a)} refers to standard supervised learning and data
selection, while \textbf{Stage~(b)} encompasses semi-supervised mechanisms
and multi-task learning.

% ============================================================================
\section{Experimental Setup}
\label{sec:setup}

The reproduction experiments (exp~210--213, corresponding to Tables~1, 3,
5, and~7) were run on the University of Bristol's Isambard-AI
platform~\cite{isambard_ai}, using a single GPU per job. The subsequent
cross-task consistency loss extension experiments (exp~219--221) were run
on the University of Bristol's BluePebble high-performance computing
platform~(BP1) under the SLURM workload manager. Both sets of experiments
followed the same configuration management and random seed control
procedures to ensure traceability and reproducibility.

On BluePebble, each SLURM job was allocated one GPU, eight physical cores,
and 64\,GB of system memory. Phase~I single-seed runs used a wall-time
limit of 24~hours, while Phase~II (exp~220) and exp~221 three-seed runs
used 40~hours, with all three seeds executed sequentially within a single
job. BP1 is a heterogeneous cluster and node assignment is managed
automatically by SLURM. The cross-task loss experiments were run
predominantly on V100 nodes with 32\,GB VRAM. All experiments ran within a
dedicated Conda environment with pinned dependencies to ensure consistent
behaviour across node types.

Random seeds were fixed across Python, NumPy, and PyTorch at the start of
every run. Each experiment's full configuration, including experiment ID,
label budget, seed, and all hyperparameters, was logged alongside model
checkpoints to support reproducibility.

All reproduction and extension experiments used a ResNet-101
encoder~\cite{he2016resnet} pretrained on ImageNet~\cite{deng2009imagenet}.
Training used the SGD optimiser with momentum $0.9$ and weight decay
$5\!\times\!10^{-4}$, following a polynomial learning-rate decay schedule
over 40{,}000 iterations. Learning rates were set to $10^{-2}$ for the
decoder, $10^{-3}$ for the backbone encoder, and $10^{-6}$ for the pose
network. Due to the single-GPU constraint, a batch size of~2 was used
without Synchronised Batch Normalisation~(SyncBN), which may introduce
minor discrepancies relative to the multi-GPU setup of the original paper.

\section{Dataset and Feature Representation}
\label{sec:dataset}

The pipeline makes use of two complementary data modalities within the
Cityscapes dataset~\cite{cordts2016cityscapes}: pixel-level semantic
annotations for supervised segmentation, and adjacent temporal frames for
geometric self-supervision.

The 2,975 fine-annotated images form the labelled pool. Low annotation
budgets of 100, 372, and 744 samples are simulated by selecting subsets
from this pool using the author-provided fixed subset indices, thereby
preserving consistency with the original evaluation protocol. For each
target image, a three-frame window consisting of the current frame and its
immediate neighbours supplies geometric cues for self-supervised depth
estimation and geometry-aware components such as DepthMix. These frames
carry no semantic annotations and are used only for photometric and pose
supervision.

Images are resized to $1024\!\times\!512$ and randomly cropped to
$512\!\times\!512$ during training. This resolution balances sufficient
spatial context for boundary-sensitive tasks against single-GPU VRAM
feasibility, particularly for Stage~(b) configurations that maintain two
parallel decoder branches simultaneously.

Several Stage~(b) components require an SDE-pretrained encoder to provide
depth-informed encoder initialisation. \texttt{fd0} refers to encoder
weights from standard monocular depth pretraining, and \texttt{fd2} refers
to weights from feature-distance regularised pretraining, which
additionally prevents forgetting of geometric representations during
downstream fine-tuning. The author-released checkpoints are used
throughout and kept fixed across all downstream experiments.

\section{Use of the PAD Multi-Task Decoder}
\label{sec:pad-decoder}

Both Stage~(b) experiments and the $\mathcal{L}_\text{ct}$ extension are
built on the PAD-Net multi-task architecture~\cite{xu2018padnet}. As
described in Chapter~\ref{chap:technical}, PAD-Net maintains two parallel
decoder branches for depth estimation and semantic segmentation on top of
a shared ResNet-101 encoder, exchanging cross-task information at an
intermediate distillation layer through an attention-guided distillation
module.

In this project's configuration, the distillation layer is placed at
decoder upsampling layer~7, producing feature maps of spatial resolution
$128\!\times\!128$ with 128 channels. The depth features $f_\text{depth}$
and segmentation features $f_\text{seg}$ at this layer serve as the inputs
to $\mathcal{L}_\text{ct}$. By explicitly encouraging alignment between
these two intermediate representations, the loss is intended to promote
the transfer of geometric information from the depth branch to the
segmentation branch at the feature level.

\section{Configuration Architecture}
\label{sec:design}

Because the project includes multiple reproduction experiments and extension
ablations with closely related but not identical settings, all
configurations are managed through a centralised \texttt{experiments.py}
module. This module acts as the central configuration reference by mapping
discrete experiment IDs to fully specified hyperparameter dictionaries,
thereby reducing configuration drift across runs and making individual
results reproducible from their experiment IDs.

The mapping is as follows. Exp~210 covers the baseline and mixing strategy
variants for Table~3 and the baseline and transfer variants for Table~5.
Exp~211 covers the SDE-guided data selection variants for Table~1.
Exp~212 covers the multi-task learning configurations for Tables~5 and~7.
Exp~213 covers the full component ablation for Table~7. Exp~219 is the
Phase~I cross-task consistency loss sweep, scanning all 32 combinations of
loss type, projection layout, warmup schedule, and $\lambda_\text{ct}$
under a single seed. Exp~220 is the Phase~II three-seed validation of
candidates identified in exp~219. Exp~221 is the extended PAD-MTL
component ablation covering MTL\,+\,DX, MTL\,+\,S, and MTL\,+\,DX\,+\,S,
each validated with three independent seeds.

\section{Experiment Groups}
\label{sec:hpc_exec}

The experimental runs fall into two broad groups. The first group
reproduces the core results reported in Tables~1, 3, 5, and~7 of the
original paper~\cite{hoyer2023ijcv_sde}, while the second group evaluates
the proposed cross-task consistency loss extension on top of the PAD-MTL
baseline. The following subsections summarise how each experiment group
was organised.

\subsection{Table~1: Data Selection (exp~211)}

This experiment curates informative labelled subsets under fixed budgets
using three selection criteria: random sampling as a baseline; entropy
sampling, which ranks unlabelled images by model prediction uncertainty;
and SDE-guided selection combining uncertainty sampling~(US) and diversity
sampling~(DS). For each criterion, images are scored and the top-$K$ are
selected to match the target budget of 100, 372, or 744 samples. The
author-provided fixed subset indices ensure exact comparability across
runs.

\subsection{Table~3: Mixing Strategy (exp~210)}

This run evaluates four training strategies under the 372-label and
full-supervision settings: a supervised-only baseline, pseudo-label
self-training, ClassMix, and DepthMix. Semi-supervised variants follow
the official teacher--student framework with exponential moving average
teacher updates and confidence-filtered pseudo-label generation. DepthMix
replaces the binary masks of ClassMix with geometry-consistent composition
masks derived from SDE depth maps, reducing boundary artefacts at class
transitions.

\subsection{Tables~5 and~7: Feature Transfer and Component Ablation
(exp~212, exp~213)}

These runs evaluate SDE-to-segmentation feature transfer using the fd0
and fd2 encoder checkpoints~(Table~5), and the combined effects of data
selection~(S), DepthMix~(DX), and multi-task learning~(MTL)~(Table~7).
Table~7 requires eight distinct configurations to isolate the contribution
of each component; each is trained with three independent seeds~(7, 25,
42) and results are reported as mean\,$\pm$\,std.

\subsection{Cross-Task Consistency Loss (exp~219, exp~220)}

The cross-task consistency loss experiments follow a two-phase design that
balances hyperparameter search coverage against result stability within a
limited computing budget.

Phase~I (exp~219) trains all 32 configurations formed by four factors,
loss type, projection layout, warmup schedule, and $\lambda_\text{ct}$,
for the full 40{,}000 iterations under a single seed. Seed~7 is used
throughout Phase~I so that all configurations are compared under identical
random initialisation conditions. The purpose of this phase is to identify
configurations that merit further multi-seed validation, while filtering
out settings that do not show competitive performance under the shared
single-seed condition.

Phase~II (exp~220) retrains the candidates selected from Phase~I using
three independent seeds~(7, 25, 42) to assess reproducibility. The
PAD-MTL baseline (without $\mathcal{L}_\text{ct}$) is retrained with the
same three seeds in the same submission batch, providing a consistent
per-seed reference for paired comparisons. Each configuration is submitted
as an independent SLURM job with a 40-hour wall-time limit, running all
three seeds sequentially.

\subsection{Extended Component Ablation (exp~221)}

Exp~221 evaluates three PAD-MTL component combinations, MTL\,+\,DX,
MTL\,+\,S, and MTL\,+\,DX\,+\,S, each with three independent seeds on
the 372-label setting, using the same pipeline as exp~219 and~220 to
ensure direct comparability with the cross-task loss results. At the time
of writing, exp~221 has been configured and submitted, but its results
have not yet been incorporated into the current analysis.

\section{Summary}
\label{sec:exec_summary}

This chapter has outlined how the experiments were organised in practice,
including the computing environment, dataset setup, model configuration,
and the correspondence between experiment IDs and the reproduced result
tables. The reproduction experiments (exp~210--213) were run on the
Isambard-AI platform and the extension experiments (exp~219--221) on
BluePebble, with both sets managed through consistent configuration
control and fixed random seeds. These details provide the implementation
context for the results presented in Chapter~\ref{chap:evaluation}.
